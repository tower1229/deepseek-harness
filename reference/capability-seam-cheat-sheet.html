Capability Seam & Tool 编写速查卡

Standards: dsh-tools & cordis
Docs: docs/cookbook/adding-a-tool.md

📐 能力缝隙（Capability Seam）三位一体角色图

角色 代码包定位 Cordis 依赖声明 核心职责与契约
1. Service Definition packages/<group>/<name> 声明合并扩展 Context 接口 声明纯接口、服务注册表、提供者选择路由策略（按 config 或单提供者自动生效），返回注销 Disposer。
2. Service Provider packages/<group>/<name>-<impl> inject: ['<serviceKey>'] 具体的平台/环境落地实现（如本地进程、云沙箱、内存缓存）。在 apply 中向 Service 注册自己。
3. Consumer (Tool) packages/<group>/tool-<name> inject: ['tools', '<serviceKey>'] 将底层服务转化为面向大模型的 defineTool，负责 Prompt 参数描述、校验、执行与 UI Card 呈现。

🛠️ defineTool 核心契约速记

  • 参数校验自动完成：parameters 声明后，execute(args, exec) 中的 args 为强类型推导结果，无需手写基础校验。
  • 输出规范（Canonical Value）：必须返回匹配 output.schema 的纯 JSON 值，不要在返回值中拼接 ANSI 码或 UI 专用 Markdown。
  • 响应取消信号：异步 IO 操作必须绑定 exec.signal（如 fetch(url, { signal: exec.signal })）。
  • UI Card 投影纯函数：presentCall 与 presentResult 必须是无副作用纯函数，严禁在其中读取全局状态或执行异步 IO。

💻 极简 defineTool 模板

import { defineTool } from '@deepseek-ai/dsh-tools'

ctx.tools.register(defineTool({
  name: 'my_tool',
  description: '面向模型的语义化描述',
  parameters: {
    target: { type: 'string', required: true, description: '目标标识' },
    limit: { type: 'number', description: '可选条数限制' }
  },
  output: {
    schema: { type: 'object', properties: { count: { type: 'number' } } },
    render: (_args, val) => [{ type: 'text', text: `完成处理 ${val.count} 条` }]
  },
  async execute(args, exec) {
    return await doWork(args.target, { signal: exec.signal })
  }
}))

⚠️ 避坑铁律（Don'ts & Best Practices）

  • 严禁单角色存在：不要写一个既直接做底层逻辑又直接注册 Tool 的孤立包。必须保持 Service 与 Tool 解耦，以便未来无缝替换沙箱或远程后端。
  • 注册皆是 Effect：注册动作必须能被 Cordis 的 Disposer 清理，切勿在全局 Map 中保留无弱引用保护的外部对象。
  • 配置快速失败（Fail Loud）：如果配置了指定的 provider 却未找到，在调用或装载时立刻抛错，严禁静默回退导致非预期行为。
