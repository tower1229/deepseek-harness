Capability Seam 三位一体架构与 Tool 开发实战

掌握 Service Definition、Provider 与 Tool Consumer 的严谨三角解耦模型

前置要求 Lesson 0001 (Cordis) & Lesson 0002 (Agent Loop)
预期用时 12 - 15 分钟
核心交付物 能独立设计并手写标准 Seam 三件套代码

1. 为什么要搞“三位一体”（Capability Seam）？

在普通 Agent 项目里，很多开发者给 Agent 加工具的方式非常随意：写一个包含 execute() 的文件，里面直接 import fs 或 axios.get()，然后注册到工具列表。

这种设计在企业级 Harness 中是严格禁止的。 思考一个现实问题：

如果你的 Agent 今天在本地 Mac 开发（直接跑本地 bash 命令），明天要部署到受限 Docker 沙盒，后天要无缝切换到云端 E2B 远程沙盒——如果你的工具和底层执行环境耦合死，你就必须对每个工具进行重构或复制一份。

Harness 提出了 Capability Seam（能力缝隙） 概念：任何能力必须严格拆分为三个独立角色：

1. Service Definition
纯接口协议与注册表管理。在 Context 声明合并对应属性，负责路由调度具体 Provider。
例: packages/shell/shell
2. Service Provider
具体的执行载体实现（本地环境、远程沙盒、内存模拟等）。依赖 Definition 并将自身注册进去。
例: packages/shell/bash-local
3. Tool Consumer
将 Service 抽象为面向大模型的 defineTool，负责 Prompt 参数校验与 UI Card 呈现。
例: packages/shell/tool-bash

价值体现： 面向模型的 tool-bash 代码永远不需要改变！只需要在 cordis.patch.yml 中把 Provider 从 bash-local 换成 bash-sandbox，整个底座的执行世界瞬间切换！

2. 实战演练：手写一个 Mini KV-Store 能力缝隙

我们以一个极简的“键值存储”（KV Store）能力为例，拆解三件套的标准落地代码。

角色 1：Service Definition (`packages/storage/kv`)

定义接口，并通过 TypeScript Declaration Merging 将类型挂载到 Cordis 的 Context： 

import { Context, Service } from '@deepseek-ai/cordis'

// 1. 扩展 Context 接口，获得全局自动补全
declare module '@deepseek-ai/cordis' {
  interface Context {
    kv: KvService
  }
}

export interface KvProvider {
  id: string
  get(key: string): Promise<string | null>
  set(key: string, value: string): Promise<void>
}

export class KvService extends Service {
  private providers = new Map<string, KvProvider>()

  constructor(ctx: Context) {
    super(ctx, 'kv') // 注册为 ctx.kv
  }

  registerProvider(provider: KvProvider) {
    this.providers.set(provider.id, provider)
    // 必须返回 Disposer 清理函数！
    return () => { this.providers.delete(provider.id) }
  }

  get activeProvider(): KvProvider {
    const prov = Array.from(this.providers.values())[0]
    if (!prov) throw new Error('No KvProvider available (Fail Loud)')
    return prov
  }
}

角色 2：Service Provider (`packages/storage/kv-memory`)

实现具体存储逻辑，并在 apply(ctx) 中向 ctx.kv 注册： 

import type { Context } from '@deepseek-ai/cordis'
import type {} from '@deepseek-ai/dsh-kv' // 引入类型声明

export const name = 'kv-memory'
export const inject = ['kv'] // 声明硬依赖！

export function apply(ctx: Context) {
  const store = new Map<string, string>()

  const provider = {
    id: 'memory',
    async get(key: string) { return store.get(key) ?? null },
    async set(key: string, value: string) { store.set(key, value) }
  }

  // 通过 ctx.effect 管理副作用，卸载时自动注销
  ctx.effect(() => {
    return ctx.kv.registerProvider(provider)
  })
}

角色 3：Tool Consumer (`packages/storage/tool-kv`)

使用 defineTool 创建面向大模型的工具： 

import type { Context } from '@deepseek-ai/cordis'
import { defineTool } from '@deepseek-ai/dsh-tools'

export const name = 'tool-kv'
export const inject = ['tools', 'kv']

export function apply(ctx: Context) {
  ctx.tools.register(defineTool({
    name: 'kv_set',
    description: '在持久化键值存储中保存数据',
    parameters: {
      key: { type: 'string', required: true, description: '存储键' },
      value: { type: 'string', required: true, description: '存储值' }
    },
    output: {
      schema: { type: 'object', properties: { success: { type: 'boolean' } } },
      render: (_args, val) => [{ type: 'text', text: val.success ? '保存成功' : '失败' }]
    },
    async execute(args, exec) {
      // args 已经由 defineTool 自动做完强校验！
      // 检查 exec.signal 响应中断
      if (exec.signal.aborted) throw new Error('Aborted')
      await ctx.kv.activeProvider.set(args.key, args.value)
      return { success: true }
    }
  }))
}

3. defineTool 的三大黄金契约

  1. Canonical Value 纯洁性：execute() 必须返回符合 output.schema 的纯 JSON 对象，绝对不要 把人类看的格式化提示（如 ANSI 高亮、表格）混进返回值。面向模型的文本放在 output.render 里，面向 UI 的卡片放在 presentResult。
  2. 必须遵守 exec.signal：大模型工具执行往往涉及网络或子进程。必须将 exec.signal 传递给底层异步 API，确保用户在点击中断时进程能立刻终止。
  3. Presentation 必须是纯函数：presentCall 与 presentResult 在会话日志 Replay（回放）时也会被调用，因此严禁在其中执行任何网络请求或读取外部未持久化的内存状态。

4. 课后即时自测

检验你对 Seam 设计与 Tool 规范的掌握：

问题 1：为什么 Harness 严禁在一个单独的包里同时写死底层 IO 操作并直接调用 ctx.tools.register()？
A. 因为多个文件打包在一起会导致 Node.js 启动变慢
B. 违背了 Seam 解耦原则：导致模型工具与具体运行环境强绑定，无法通过替换 Provider 无缝切换沙盒或远程环境
C. 因为 TypeScript 编译器不支持在一个包里同时 export 工具和执行逻辑
问题 2：在编写 defineTool 时，如果需要向 Web 界面返回一个带有语法高亮的文件变更 Diff 卡片，应该写在哪里？
A. 在 execute() 的返回值里直接拼好 HTML 字符串
A. 在 output.render 里返回带 ```diff 的 Markdown 文本
C. 通过 output.presentationMeta 投射元数据，并在 presentResult 纯函数中返回 card: diff 结构
