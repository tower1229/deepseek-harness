🔄 Turn vs Step 边界对比

维度Turn (轮次)Step (单步)
定义 完整业务响应周期（从收到输入到无可做工作） 单次“模型请求 + 工具执行”闭环
包含关系 包含 0 到 N 个 Steps 严格隶属于一个 Turn
Inbox 认领 认领 1 条 Queued Prompt + Next-step Input 仅认领步间产生的 Next-step Input
会话事件 turn/start → turn/end step/start → step/end

📜 核心公理：Model-Visible ⟺ Logged

  • 无独立状态：内存中没有常驻的 messages: Message[] 数组。
  • 纯函数投影：模型每次看到的历史全部由 session.deriveMessages() 从持久化的 SessionEvent[] 流中确定性计算得出。
  • 不可变追加：所有对模型可见的事实（用户输入、助手回复、工具输出）必须以持久化事件落地，杜绝内存暗流。
  • 零 Key 回放：所有 snapshots/ 录制会话仅需重放 Event Log 即可 100% 还原行为。

⚡ 核心事件与扩展点分类表

事件名称 机制属性 触发时机与职责 监听规范
agent/pre-step Waterfall Step 开始前。决定认领的消息是否进入 Step：enter() 或 reject() 必须调用 next() 传递决策，支持消息重写
agent/request Waterfall 向 LLM 发起请求前。可注入/重写 Prompt、模型参数或选择 Adapter 必须调用 next()
agent/turn-stopping Serial Turn 自然结束且无待处理输入时触发。最后拦截检查点（如 Ralph/Goal 驱动） 无 next()，顺序执行异步钩子
session/event Durable Broadcast 每次 session.append() 成功落盘并冻结时全局广播 只读观察者，UI 渲染/持久化存储均订阅此流

🛠️ 工具调用并发与屏障

  • executionMode: 'parallel'：默认只读/幂等工具（如 read_file、grep）。由有限滚动并发池执行，并发上限为 maxParallelToolCalls（默认 10）。
  • executionMode: 'exclusive'：写操作/状态破坏工具（如 write_file、bash）。作为屏障，前后并行任务必须排空后单独串行执行。
  • Model-Ordered 排序：并发完成次序无论先后，在 Session Log 与 UI 派发时始终严格按照模型输出的原始顺序提交。

🔍 调试与验证命令

  • pnpm run test:snapshot -t <name>：使用录制的 Session Log 执行零 Key 确定性回放测试。
  • pnpm dsh --profile headless --dump-config：打印运行时的完整插件装配图。
  • session.snapshotEvents()：在测试或调试断点中获取不可变事件切片。
  • deriveMessages()：验证事件流解析出的模型上下文输入。
