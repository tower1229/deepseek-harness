1. 核心世界观：没有特权内核，一切皆是插件

在大多数传统的 AI Agent 框架中，往往存在一个中央引擎（如 AgentEngine 类），它硬编码了模型调度、工具执行、日志收集和持久化等逻辑。外部扩展通常通过继承基类或注册回调函数来实现。

DeepSeek Harness 的根本设计哲学：
There is no privileged core.（系统没有特权内核）。系统底层是 Cordis 微内核。包括 LLM Adapter、Tool Registry、Session Event Log，甚至是驱动多轮对话的 Agent Loop 本身，全都是平等的 Cordis 插件。

这意味着：扩展 dsh 不是去修改核心，而是在现有插件旁边挂载新的插件，或通过补丁覆盖现有插件。 当插件被卸载或发生重载时，注册的 Service 和 Event 监听器会通过 Effect Disposer 自动全部回滚。

2. 应用启动链：从 Profile 到最终 Context

所有支持的 Node 运行入口（Web UI、Headless 跑批、SDK 守护进程、ACP 自动化等）全部收敛在同一个 CLI 命令：dsh。代码位于 packages/boot/app-boot。

1

CLI 接收 Profile 参数

例如执行 dsh --profile headless "fix bug" 或 dsh web（即 --profile web 的别名）。

2

查找 Profile 声明并解析 Bundle 列表

每个 Profile 会按固定顺序组合 Bundle。例如 headless 组合了：dsh-base（基础层） + dsh-headless（单次运行驱动层）。

3

顺序应用配置补丁（Patch Layers）

按照严格优先级应用：
Bundle 默认声明 → Profile 级 cordis.patch.yml → Home 级 cordis.patch.yml → --patch 命令行注入。
每一层都可以按插件 id 整体覆写该插件的 config，或禁用插件。

4

Cordis Loader 启动与拓扑排序加载

Cordis 遍历配置条目，解析每个插件导出的 inject: string[] 依赖声明。只有当一个插件所依赖的所有 Services 全部就绪时，它的 apply(ctx) 才会被调用。

3. 动手实操验证：Dump 真实的运行时配置

🛠️ 本地终端实操

在当前仓库根目录运行以下命令，直观查看 Harness 实际装配的 Cordis 插件树：

pnpm dsh --profile headless --dump-config

请在输出中重点寻找这几行关键特征：

  • # == @deepseek-ai/dsh-base, patched by @deepseek-ai/dsh-headless：说明了 dsh-headless 是如何对 dsh-base 中的 tools 和 system-prompt 注入补丁的。
  • id: agent-loop：Agent 核心驱动是以普通插件身份挂载在 @deepseek-ai/dsh-base 底座上。
  • !!js process.env...：配置文件支持合法的 JS 表达式动态求值（注意必须是两个感叹号 !!js）。

4. Cordis 插件编写核心契约

编写一个合规的 dsh 插件，最简骨架如下：

import type { Context } from '@deepseek-ai/cordis'

// 1. 唯一插件名
export const name = 'my-custom-feature'

// 2. 声明所需服务依赖（只有当 ctx.tools 和 ctx.sessions 都存在时才执行 apply）
export const inject = ['tools', 'sessions']

// 3. 插件装载入口
export function apply(ctx: Context) {
  // 注册一个生命周期受控的副作用 (Effect)
  // 当该插件卸载时，ctx 自动调用返回的清理函数，不会留下悬空事件或泄露
  ctx.effect(() => {
    const dispose = ctx.tools.register(/* ... */)
    return () => dispose()
  })
}

黄金法则（Misconfiguration fails loud）：

如果插件的依赖服务缺失，Cordis 不会静默降级或吞掉错误，而是在启动阶段立刻抛出明确的未满足服务名称并报错退出。这保证了生产环境绝不会带病运行半初始化的 Agent。

A. 直接在 packages/core/tools/src/index.ts 中硬编码默认模式

C. 在运行中通过全局全局变量 global.dshConfig 动态篡改
问题 2：Cordis 中的 inject: ['systemPrompt'] 机制起到了什么作用？
A. 将 systemPrompt 包的所有内部私有函数直接引入当前文件
B. 声明依赖约束：确保 Context 上已就绪 systemPrompt 服务后才激活当前插件，缺失则启动报错
C. 仅仅是供 TypeScript 编译器做静态类型推导，没有运行时作用
